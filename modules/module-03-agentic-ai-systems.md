# Module 3 — Understanding Agentic AI Systems

## How LLMs, Tools and Memory Make an AI Agent

An AI agent isn't a different kind of model — it's the same large language model wired up with a few additional pieces that let it act in the world instead of just talking about it. Understanding those pieces is what makes the rest of this course click, because everything Claude Code does traces back to this basic loop.

- **The LLM as the reasoning engine.** At the center of any agent is a language model doing what it always does: taking in text and predicting what should come next. In an agent, that "next" isn't just conversational reply text — it can be a decision about which tool to call and with what arguments. The model itself has no ability to run code, browse the web, or touch your filesystem; it can only generate text that describes an intended action.
- **Tool use (function calling) turns text into action.** An agent framework defines a set of tools — a "read file" tool, a "run a shell command" tool, a "search the web" tool — each with a name, a description, and the parameters it expects. The model is told what tools are available and picks one when it decides an action is needed. The surrounding system then actually executes that tool call (running the real command, reading the real file) and returns the result to the model as new input. The model itself never executes anything directly — it only ever proposes calls, and the harness carries them out.
- **Memory and context give the loop continuity.** An agent needs to remember what it already tried, what worked, and what the current state of the world looks like. Some of this lives in the context window as ordinary conversation history — previous tool calls and their results are fed back in as text. Some of it is more durable: project-level instructions (like a CLAUDE.md file) that get loaded at the start of every session, and auto-generated memory that persists learnings across sessions rather than being lost when the context window fills up or a conversation ends.
- **The perceive–act loop is what makes it "agentic."** A single request/response pair is not an agent — that's just a chatbot. An agent runs a loop: it perceives the current state (the user's goal, the results of its last action, the current file contents), decides on the next action, executes it via a tool, observes the outcome, and decides whether to continue, adjust course, or stop because the goal is met. This loop can run for many iterations without a human approving each individual step, which is both the power and the risk of agentic systems — it's why permissions and guardrails (covered in Module 5) matter so much once you start using one.
- **Claude Code is a concrete, working example of this whole picture.** The model reasoning about your request is Claude. The tools are things like reading and editing files, running bash commands, and searching your codebase. The memory is your project's CLAUDE.md file plus the auto memory Claude Code builds as it works, both of which persist context across sessions without you re-explaining your project every time. And the loop is what you actually watch happen when you give Claude Code a task: it reads relevant files, makes an edit, runs your test suite, sees a failure, and adjusts — entirely on its own, checking back in with you only as often as your permission settings require.
- **This is also why "agentic" is a spectrum, not a binary.** A tool-calling model that only ever makes one tool call before replying is agentic in a thin sense. A system like Claude Code that can chain dozens of tool calls together, coordinate multiple sub-agents (Module 13), and work for extended periods against a single goal is agentic in a much deeper sense. As you move through this course, you'll see the same LLM-plus-tools-plus-memory pattern show up again at every layer — skills, hooks, MCP servers, and subagents are all different ways of shaping what an agent can perceive and what actions it's allowed to take.
- **"AI agent" and "agentic AI system" get used loosely, but they're not quite the same thing.** An AI agent, strictly, is the smallest unit of this pattern: one LLM plus a set of tools, running the perceive-act loop described above. An agentic AI system is the bigger picture — one or more agents plus memory that persists across runs, plus connectors to other tools and services, sometimes plus multiple agents coordinating with each other. Claude Code by itself, in a single session, is an AI agent; Claude Code with a CLAUDE.md file, saved memory, MCP servers, and sub-agents delegating work to each other is the fuller agentic AI system. It's worth knowing the distinction exists so you're not confused when a course, a docs page, or a colleague uses the two terms in slightly different ways.
